API

Everything gritz does, from the Web UI to the CLI and the runners, goes through one service, gritz.v1.GritzService. A program with an API key can call it too. Its full definition is at the end of this page.

Endpoint

Section titled “Endpoint”

Every RPC is a POST to its own path on the server:

On a self-hosted server, replace https://gritz.dev with its base URL.

Protocols

Section titled “Protocols”

The server speaks the Connect protocol, gRPC and gRPC-Web, so any Connect or gRPC client generated from the service definition can call it. With Connect, a request body is the request message as JSON (Content-Type: application/json) or binary protobuf (Content-Type: application/proto). JSON field names are the camelCase form of the proto field names: page_size is pageSize.

Authentication

Section titled “Authentication”

Send an API key as a bearer token:

The key acts for the organisation it was created in, and can call what a member can. A request without a valid key fails with the unauthenticated code.

Section titled “Example”
