Fake runner backend

Issue: https://github.com/gritzapp/gritz/issues/1760

Problem

Section titled “Problem”

The runner tests (internal/runner/taskmanager_test.go, internal/runner/taskrunner_test.go) are in package runner. They assert on TaskRunner’s and TaskManager’s private fields (tr.sbx, tr.rec, tr.running, m.tasks, m.sem, m.store, …), so renaming an unexported field breaks the test build. That happened with sb -> sbx, fixed in #1779. They also rebuild sandbox behaviour in each test from backend.SandboxMock / BackendMock closures (testSandbox, testBackend, about 100 Func uses). Each of those is a partial copy of the contract documented on backend.Sandbox.

#1760 moves the tests to package runner_test, using only the exported API, on top of a stateful fake backend. This proposal covers its first step: the fake, internal/runner/backend/fake. It also re-checks #1760’s “Replacing internal access” table against master after #1758, and lists the exported runner API the migrated tests need.

The fake is built and tested here. Migrating the tests is the later slices of the Implementation Plan.

Design

Section titled “Design”

Package and scope

Section titled “Package and scope”

internal/runner/backend/fake is an in-memory backend.Backend for tests. It is a normal package, not a _test.go file, so runner_test (and later other packages) can import it. Production code never imports it.

It is deliberately small:

  • It implements the backend.Sandbox state machine and nothing else of a platform. It has no transitional states (SUSPENDING, pausing), no images and no files. A test that needs a transitional state’s effect injects it with FailNext (a plain error from Start, as backend.Sandbox.Start documents).
  • It does not import driverserver. A sandbox’s driver is a DriverServiceClient the test provides (see Driver hookup).
  • It implements backend.RunEnver unconditionally. RunEnv returns Options.RunEnv(ws) when that is set, and nil otherwise, which TaskManager.runSpec’s maps.Copy treats as no environment. This replaces runEnvBackend, which embeds *backend.BackendMock today.
  • ValidateWorkspace accepts every workspace.

State machine

Section titled “State machine”

Each sandbox the fake holds is in one of four states:

The table below gives each operation’s result per state. It is the contract on backend.Sandbox, applied to the fake:

Op created up parked gone
Status StatusParked StatusUp StatusParked StatusGone
Start -> up no-op -> up ErrGone
Park no-op (stays created) -> parked no-op ErrGone
Destroy -> gone -> gone -> gone nil, no change
Dial client client client client
Handle fixed fixed fixed fixed
  • Gone is terminal. Nothing leaves it. IDs are never reused, so a gone sandbox stays in the fake’s observations for the rest of the test.
  • Handles share state. A fake.Sandbox value is only {backend, id}. All state lives in the backend’s table, keyed by ID. Create and every Open of the same ID return values that see the same sandbox, so Open after Create, two Opens of one handle, and the Open of a second TaskManager on the same fake (a runner restart) all observe and change one sandbox.
  • Stale handles. Open does no I/O and does not check the table, as on every real backend. A handle whose ID the fake never had, or whose sandbox is gone, behaves as gone: Status is StatusGone, Start and Park return backend.ErrGone, Destroy returns nil.
  • Open validation. Open fails only for a handle of another Type or with an empty ID, as Docker’s does. Data is ignored, and Handle() returns the sandbox’s own handle ({Type, ID}, no Data), as Docker’s does. So a legacy record’s Data disappears from the record the next time the TaskRunner writes it, as in production.
  • IDs. Create names sandboxes c1, c2, … in call order, skipping IDs that Add already used. The handle type is Options.Type, defaulting to "fake".
  • Create errors. A Create that fails (through FailNext) leaves no sandbox, as backend.Backend.Create requires. Its spec is still recorded in Specs.
  • Dial never fails and never checks the state: it only returns a client. Whether the driver answers depends on the state (see Driver hookup).
  • Concurrency. One mutex guards the table. Every method is safe for concurrent use, as backend.Sandbox requires. Hooks and driver handlers run without the lock held.

Controls

Section titled “Controls”

A test changes the fake from outside the runner through three methods:

  • Add(id, state) puts a sandbox into the fake as if a previous runner process had created it, and returns its handle. The test writes the matching taskstate.Record and then calls Load or TaskRunner.Restore. This replaces track / seed. A sandbox added Up has a driver like any other.
  • Set(id, state) moves a sandbox the way the platform or an operator would, without the runner knowing: Gone is docker rm or a terminated VM, Parked is a container that exited, Up is someone running docker start. Set cannot move a sandbox out of Gone and panics on an unknown ID: both are test bugs. A Set to Gone is not recorded in Destroyed, which keeps “the runner destroyed it” apart from “it vanished”.
  • FailNext(op, id, err) makes the next call of op on sandbox id return err without changing state. id "" matches any sandbox, and is the only form that makes sense for OpCreate. Failures queue: two FailNext calls for the same (op, id) fail the next two calls. Failures are scoped to one sandbox because Prune walks the registry in map order: a failure that “the next Status anywhere” consumes would pick a random task. Ops cover every method that can fail: OpCreate, OpOpen, OpStart, OpPark, OpStatus, OpDestroy, OpDial. OpDial matters because a real Dial can fail (Lambda’s does), and TaskRunner handles that in Kill, startRun and attachOnce; a failed Dial returns no client and is not counted in Dials.

A fourth method, Drop(id), cuts every Run call the runner has open on the sandbox’s driver without changing its state (a network blip). It replaces hs.CloseClientConnections() in TestTaskRunnerRun_Reattach, which becomes waitRuns(1), one Drop, waitRuns(2) and stopRun, with no sleep loop.

A fifth, SetDriverReady(id, ready), models a sandbox that is up while its driver is not listening yet: while the sandbox is up and its driver is not ready, Status, Run and Stop fail with CodeUnavailable, and making it not ready cuts the open Run calls, as Drop does. Drivers are ready unless Options.DriverNotReady is set, which makes every sandbox, added or created, start with its driver not ready. This replaces the ready channel that newDriver wrapped around the driver as a 503 gate (Poll_SlowDriver, Run_NotReady, Start_NotReady, Wait_Done). Readiness is not in Info: the test that sets it knows it.

Observations

Section titled “Observations”

Snapshot() returns a copy of the fake’s state:

  • Sandboxes: every sandbox the fake has held, in creation order, gone ones included. Each is an Info with its handle, task, state, the Spec it was created from (nil for Add), and how many calls of each operation succeeded on it (Starts, Parks, Destroys, Dials). These counters replace sb.StartCalls(), ParkCalls(), DestroyCalls() and DialCalls(). A call that FailNext failed, or that returned ErrGone, is not counted. A no-op is: Start on an up sandbox counts, because the runner made the call. That is what lets a trailing Start prove which sandbox a TaskRunner holds (see Probing what a TaskRunner holds). Info.RunSpecs is a deep copy of the RunSpec of every Run request with one (a request to start a run) sent to the sandbox’s driver while up, in order (see Driver hookup). This replaces the tests that call m.runSpec directly. Info.Runs counts the Run calls that went through, incremented in the same critical section that registers the call’s cancelable context. Since Drop, leaving up and Close cancel every registered call, Runs >= n means the n-th stream can be cut deterministically. Tests wait on it (waitRuns) for “the runner has attached”, rather than on Dials, which a Dial bumps before any stream is opened.
  • Specs: a deep copy of every Spec passed to Create, in call order, including those that failed. This replaces be.CreateCalls()[0].Spec and the tests that read m.spec directly.
  • Destroyed: the IDs that Destroy moved to gone, in order.
  • Helpers Sandbox(id) and Live() (sandboxes that are not gone).

Waiting without sleeps. Wait(ctx, cond) blocks until cond holds for the current snapshot, or ctx is done. Every change to the table (a state change, a counter, a spec) closes and replaces a changed channel, and Wait re-checks cond each time it fires. Nothing polls. WaitState(ctx, id, state) is the common case. This replaces the mock-counting waitDialed (now waitRuns, on Info.Runs) and the parked channel testSandbox returns.

Driver hookup

Section titled “Driver hookup”

Options.Dial func(backend.Handle) driverv1connect.DriverServiceClient returns the test’s client to a sandbox’s driver. In runner_test that is the client serveDriver already gives the test, over an httptest.Server serving a real driverserver.Server’s handler, so the fake never imports driverserver. A driver that is not listening yet is the fake’s SetDriverReady (see Controls), not a gate on that server.

The fake calls Options.Dial on every Dial, without its lock held, and wraps the result in its own DriverServiceClient, which makes the driver follow the sandbox’s state:

  • Status and Stop fail with CodeUnavailable while the sandbox is not up or its driver is not ready, the same as a driver that is not answering, and call through otherwise. A nil Dial, or a Dial that returns nil, gives a sandbox whose driver never answers (TestTaskRunnerRun_DriverUnreachable).
  • Run makes the same check. Then it counts the call in Info.Runs, records the request’s RunSpec, if it has one (a request to start a run), in Info.RunSpecs, and calls through with a context the fake cancels when the sandbox leaves up (Park, Destroy, or Set to Parked or Gone), as stopping a container kills its driver, on Drop, when its driver is made not ready, and on Close. An attached Run stream ends, and attach then sees the new Status. This is what lets a test make a sandbox vanish under a run with one call.

A stream the fake cuts ends with CodeCanceled, not the transport error a real dropped connection gives. attach treats it like any drop and reattaches. startRun’s accept loop only retries CodeUnavailable, though, so a test must not cut a sandbox while a start is being accepted: the start would fail rather than be retried.

The fake forgets a call’s cancel func only when the call’s context is done: ServerStreamForClient is a concrete type, so it cannot see the stream close. attach opens stream after stream on the run’s context, so one entry accumulates per reattach for the life of a run. That is harmless in a test, and noted in the code.

The in-process driver outlives the sandbox’s state. Parking the fake does not stop the run inside driverserver, and starting the fake again does not restart it. A test that needs the run to end stops it through the driver, as today (stopRun). Tests that start a run on the driver themselves (serveDriver) use the same client unwrapped. That test-side client is not gated, because the test stands inside the sandbox.

Dial’s JWT is ignored, as a driver with no runner key ignores it.

API

Section titled “API”

How it fits: a runner_test test calls fake.New with a Dial giving its client to a real driverserver, and passes the result as TaskManagerOptions.Backend or TaskRunnerOptions.Backend. It arranges sandboxes with Add, Set and FailNext, drives the runner through its exported API, and asserts on Snapshot and Wait, next to the taskstate.Store and the gritzclient.ClientMock it already owns.

Exported runner API the tests need

Section titled “Exported runner API the tests need”

The rewrites below need two additions to internal/runner. The TaskRunner and TaskManager surfaces stay as #1758 left them otherwise. In particular, there is no accessor for what a TaskRunner holds: tests find that out by driving it (see Probing what a TaskRunner holds).

  • ErrRunning. TestTaskRunnerStart and TestTaskRunnerStart_Concurrent assert that a second Start refuses with it. It is part of Start’s documented contract, and Poll already branches on it.

  • TaskManager.Wait. “The Run is done” is what waitIdle and waitReleased wait for, and every negative assertion after a run needs it: attach parks the sandbox before Run sends its TaskLostEvent. So “sandbox parked, outbox empty” passes even when an event is about to arrive. The fake sees the park; only the manager sees the goroutine return. A sync.WaitGroup around m.run’s goroutine (Done deferred, so it runs after Release and Wake, and on the shutdown path that skips them) gives that without exposing m.sem.

    Wait is only for when nothing can start another run: Poll, Load and Run’s loop must all be done or not yet called. Each of them reaches m.run, whose WaitGroup.Add from a zero count while WaitGroup.Wait is blocked is a misuse of sync.WaitGroup. Shutdown meets that condition (Run has returned). A test meets it by calling Wait only after its last Load, Poll or Start has returned, and never while m.Run is running.

    It is also the missing step in gritz runner’s shutdown, where the deferred m.Close() closes the backend while Run goroutines may still be unwinding. Wiring it in there is a separate fix: PR (see Decisions).

Calling TaskManager.Start directly without holding a slot, as the rewritten tests do, is harmless: safesem.Release floors at zero. So startTask’s TryAcquire goes away. Tests about admission go through Poll.

Probing what a TaskRunner holds

Section titled “Probing what a TaskRunner holds”

Today’s tests read tr.sbx and tr.rec to see whether a TaskRunner still holds a sandbox. The rewritten tests find out by driving it: they call Start on it and look at what the fake saw.

  • A new Create (one more entry in Snapshot().Specs, a new sandbox c2) means it held no sandbox.
  • No Create, and one more Start on c1 (its Starts counter went up) means it still held c1.
  • ErrRunning means it is claimed, and nothing about the sandbox can be learned that way. Only Restore on an up sandbox claims without a Run, and it claims in the same lock acquisition that installs the sandbox, so for Restore the claim is itself the proof that the sandbox was adopted.

The record half needs no probe: the store is the test’s own. The fake half needs no probe either: Snapshot shows what is live and what was destroyed.

The probe changes state. It may create a sandbox, starts one, and restamps the record with the probe’s version, so it is always the last thing a test does with that TaskRunner. In the middle of a test, the next act usually already is the probe: in Start_Gone, the second Start creating c2 proves that the first one left nothing behind. Where it is not, the test checks only the store and the fake at that point.

TestTaskManagerHandleEvents_Fatal uses the same probe. Its store’s directory is removed, so a missing record proves nothing. A trailing m.Runner(1).Start makes a second Create (two Specs), which proves the failed write left the TaskRunner with no sandbox. The probe’s own record write fails as well and sends a second TaskFatalEvent, which is harmless: the first cause wins.

Differences from #1760’s table:

  • waitIdle cannot be “the fake sandbox reaching parked”. As above, parking comes before the lost event, so “parked” does not mean “done”. Hence TaskManager.Wait. For a tr.Run the test calls itself, Run returning is enough.
  • track / seed use TaskRunner.Restore where the test does not want Load’s side effects (a Run goroutine for every up sandbox, GetTask for every parked one). Restore is exported and does exactly what seed did, plus the claim of an up sandbox.
  • No timing fields need adding: #1758 already put them on TaskRunnerOptions.
  • No accessor for what a TaskRunner holds. The issue left tr.sbx to “the fake’s live sandboxes”. Those show what exists, not what the TaskRunner holds, so the tests add a trailing Start probe.

Shared helpers and backendtest

Section titled “Shared helpers and backendtest”

Neither is needed for the fake, so both stay out of this proposal:

  • The helpers (testStore, testManager, submitted, waitQueued, assertTracked, the driver helpers) move with the tests into internal/runner/helpers_test.go in package runner_test. They stay unexported and test-only. A shared internal/runner/runnertest package is worth it only once a second package needs them, and nothing does yet.
  • The fake’s own tests are a table over (state, op) → (result, new state), the table in State machine. They are written to take a backend.Backend plus a way to put a sandbox in a state, so a later backend/backendtest conformance suite can lift them and run them against Docker and Lambda as well. That suite is its own follow-up.

Validation: rewritten tests

Section titled “Validation: rewritten tests”

The tests below are today’s, rewritten as package runner_test against the fake and the two additions above. They assume these helpers in helpers_test.go, ported from today’s:

  • testStore(t, recs...), submitted, waitQueued: unchanged.
  • testManager(t, be, store, tune...): unchanged, but with runner. prefixes.
  • driverClient(t, version) driverv1connect.DriverServiceClient: today’s newDriver, returning only the test’s client, and without its ready channel: a slow driver is fake.Options.DriverNotReady and SetDriverReady.
  • waitRuns(t, be, id, n): waits on be.Wait until Info.Runs >= n, for “the runner has attached”.
  • serveDriver(t, taskID, version, cfg) driverv1connect.DriverServiceClient: as today, returning the test’s client, which also goes in fake.Options.Dial.
  • drivers(client) func(backend.Handle) driverv1connect.DriverServiceClient: every sandbox gets the driver client reaches.

assertRecord checks the store only, so it can go anywhere in a test. assertTracked adds the probe, so it goes last:

The old helper told “no TaskRunner” apart from “a TaskRunner with no sandbox”. #1758 made that difference meaningless, and the tests do not look at the registry, so the two cases merge here: either way, the probe creates.

assertTracked: a sandbox that fails to start

Section titled “assertTracked: a sandbox that fails to start”

Replaced: testSandbox(nil) + StartFunc, BackendMock.CreateFunc, startTask (the slot), sb.DialCalls(), sb.DestroyCalls(), and the private assertTracked. The first assertTracked of the original, in the middle of the test, becomes assertRecord plus the fake’s view: a probe there would start c1. The Destroy that follows is the drive that shows the TaskRunner still held c1. The trailing assertTracked probes with a Start that creates c2.

waitIdle: a runner restart mid-run

Section titled “waitIdle: a runner restart mid-run”

waitIdle(first.Runner(1)) and waitReleased(m) both become Wait. One assertion is dropped: !first.sem.TryAcquire(1) (“a shut-down manager still holds the slot”). The process it describes is exiting, so no caller can observe it. What matters for the next boot, that the sandbox stays up and unparked, is still asserted, through the fake. The two managers share one sandbox only because Open shares state by ID, which BackendMock faked by returning one *SandboxMock from OpenFunc.

Gone-sandbox restore

Section titled “Gone-sandbox restore”

The gone row and the new never existed row are the gone-sandbox restore: a sandbox that vanished since the record was written, and a record whose ID the platform never knew. Both give StatusGone through the stale-handle rule with no mock. Before, each was a StatusFunc returning the constant. The “claimed” (tr.running) and “has a sandbox” (tr.sbx) assertions no longer read fields: one trailing Start answers both. It refuses when claimed, starts c1 when the TaskRunner kept it, and creates when it did not. The status error row shows why a no-op Start counts: c1 is already up, and the probe still has to see the TaskRunner reach it.

Gone at Start, then a fresh sandbox

Section titled “Gone at Start, then a fresh sandbox”

Before, this test needed two mocks wired differently (OpenFunc returning gone, CreateFunc returning fresh) and a StartFunc returning ErrGone. Now it needs one Set. The fresh sandbox’s ID (c2, not a second c1) and the empty Destroyed are behaviour the mocks could not express. The original assertTracked(t, m, 8, nil) in the middle becomes assertRecord. The second m.Start creating c2 is the probe that shows the TaskRunner held nothing.

Trade-offs

Section titled “Trade-offs”
  • A fake over shared mock helpers. Better SandboxMock builders would shrink the closures but still let every test define its own semantics, so a test could pass against behaviour no backend has (a mock Status saying up after a Park). The fake has one state machine, and it is the contract on backend.Sandbox. The cost is that tests can no longer pin an arbitrary sequence of results. FailNext covers the cases today’s tests need.
  • A wrapped client instead of an http.Handler. Slice 3 had the test hand the fake an http.Handler, served on an httptest.Server per sandbox, so the fake could gate requests on state and drop connections. Recording the RunSpec of a request then meant decoding the Connect envelope in that gate, which is too brittle for a test fake. Wrapping the test’s DriverServiceClient gates on state just as well. It sees typed requests, so recording a spec is one line, and it cuts a Run by cancelling its context. The cost is that a cut stream ends with CodeCanceled rather than a transport error (see Driver hookup), and that the fake’s gate covers only the three methods the client has today.
  • No Before/hook API. A hook run before each op (for “the record is written before Start” assertions, or blocking Create) is more general than FailNext, but it brings back per-test closures. A record that survives a FailNext(OpStart) already shows the write came first, and TestTaskRunnerStart_Concurrent’s 10ms Create sleep is not needed: tr.mu serializes the two Starts either way.
  • TaskManager.Wait over a Claimed() accessor. TaskRunner.Claimed() would expose the claim flag and still need polling to wait on it. Wait is a blocking primitive with a production use.
  • Probing over a TaskRunner.Record() accessor. An accessor for the in-memory record would let assertTracked check the TaskRunner without changing it, and could go anywhere in a test. But it asserts on state rather than behaviour, and it would be API that exists for tests only. A trailing Start checks what matters, that the next run lands on the right sandbox, through the API production uses. The cost is that the probe changes state and must go last, and that it cannot see past a claim. The only claim without a Run is Restore on an up sandbox, and that claim is itself the proof.
  • No registry accessor. A TaskManager.Registered(id) accessor would expose the registry purely for tests. The tests reach a task’s TaskRunner through m.Runner only to drive it, and observe Prune and the rest through the fake, the store and behaviour. Since #1758, “no TaskRunner” and “no sandbox” mean the same thing to every caller.
  • Dropping the defaults half of TestNewTaskRunner. Keeping it would need either tr.opts (internal) or an options accessor. It only restates the default* constants, so it is dropped rather than kept internal.
  • Helpers stay in helpers_test.go. A runnertest package now would export test helpers with one importer, and turn their signatures into an API to maintain.

Decisions

Section titled “Decisions”

Settled in review:

  • TaskManager.Wait in gritz runner. internal/command/runner.go returns from m.Run, and its deferred m.Close() closes the backend while Run goroutines may still be unwinding. Calling m.Wait in between is a behaviour change, so it is a separate fix: PR, not part of this stack.
  • eventoutbox_test.go moves to runner_test in slice 7. Its TestIsPermanentError called the unexported isPermanentError, so it becomes TestRunnerEventOutbox_Permanent: an event delivered through NewRunnerEventOutbox whose first SubmitRunnerEvents fails, asserting whether the store dead-lettered it (Drop(true)) or it was retried. After the migration, internal_test.go (TestDoubling) is the only test file left in package runner.
  • No FailAlways, no FailNext count until a test needs one. Every failure today’s tests inject is a single call.
  • backendtest comes after the migration, as a follow-up outside this plan. The fake’s state-table test is shaped so that suite can lift it.
